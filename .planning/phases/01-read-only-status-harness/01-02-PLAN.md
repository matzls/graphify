<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Script CLI args -> harness core | User-provided paths and profile names must be resolved safely and reported clearly. |
| Harness -> Second Brain target repo | Target repo must remain read-only; status before and after run is acceptance evidence. |
| Harness -> local report directory | Reports are controlled local evidence and must avoid secret/body leakage. |
| Harness -> Ollama | Readiness checks can touch local service metadata but must not trigger target semantic refresh. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-06 | Tampering | `scripts/graphify_status_harness.py` target invocation | mitigate | Compare target `git status` and `HEAD` before and after baseline run; fail if changed. |
| T-01-07 | Information Disclosure | saved JSON/Markdown reports | mitigate | Persist compact evidence under `.planning/phases/01-read-only-status-harness/reports/`; do not embed raw target file contents. |
| T-01-08 | Repudiation | baseline evidence | mitigate | Save timestamped or deterministic baseline JSON and Markdown with fork root, target root, target HEAD, and diagnosis evidence. |
| T-01-09 | Denial of Service | live status script | mitigate | Keep default script to readiness/probes only with bounded subprocesses; no semantic refresh or stress run by default. |
| T-01-10 | Spoofing | path/profile selection | mitigate | Require explicit `--target-root` override when not using the known profile root and include resolved roots in JSON evidence. |
| T-01-SC | Tampering | package installs | mitigate | Script uses existing project code; `uv sync --group dev` may install the Plan 01 declared pytest dev dependency from the RESEARCH.md Package Legitimacy Audit before verification. |
</threat_model>
